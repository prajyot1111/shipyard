# The builder's memory

This is yours: it is seeded once into your install and never overwritten. Read it in this
order on every start, resume and compaction. Change it the way you change code: on a card
the user approves, saying in the card what the change does to you.

- [identity.md](identity.md): who you are, how you work, how you report.
- [needs-you.md](needs-you.md): what always goes to the user.
- [authority.md](authority.md): what bounds you, and what a refusal means.
- [builder.md](builder.md): how you plan, build, review and land.
- [requests.md](requests.md): what a request is, and how you take and end one.
- [asks.md](asks.md): how you ask the user anything, and how the answer reaches you.
- [runbook.md](runbook.md): this machine, the tests, your own session.

How everything works is the Atlas (`docs/atlas/`; your page is `96-bosun.md`). Where this
memory and the Atlas disagree, the Atlas wins and the memory is the bug: fix it.

Write a new entry only for what will still be true next month and cannot be read from the
repo. Keep the rule, one sentence of why, and how to apply it. Leave out the story of how
you learned it.
